# Existing ConvoMem HTML film integration

Reused the latest existing source from `convoMem/Marketing roadmap/marketing-video/v4.html` rather than producing a replacement animation. The original folder and renders are untouched. The website copy is `public/media/convomem-film/v4.html`, with its two local fonts and the original mixed soundtrack.

The hero and expanded dialog both play the complete 2:35 customer story. Clicking or tapping the image toggles play/pause; the separate transport controls remain available. Both players start muted. Original narration, dialogue and soundtrack are available through the sound control. The soundtrack is copied without re-encoding from the original final-v4.mp4 export. Its AAC packet SHA-256 matches the export exactly: 00b649d249a0062ee2b2b1da975721f2e8656c9c7887b7db98851f3fbdcd0684. One native audio clock drives the HTML timeline, replacing independently started voice clips and music. Original cue metadata still drives captions. Included the music attribution required in the source and font licenses.

Kept the existing artwork, scene choreography, narration, customer story, and original logo. Added a same-origin synchronous control interface (preserving media user gestures) with a source-checked message fallback for transport controls, seek, state and sound. Parent controls stay 44px at phone widths instead of being scaled down with the 1920×1080 canvas. The full player supports fullscreen. Background/offscreen playback pauses; reduced-motion preferences use a static preview until deliberate playback. The embedded HTML is excluded from search indexing.

QA: checked real playback, timeline advance, pause/resume, sound-on narration plus music, sound-off muting audio, muted initial state, expanded viewing and 390px phone layout. Source asset uses the existing custom narration captions and dialogue transcripts. Existing copied-film CSS/style lint warnings remain warnings; the UI typecheck, content tests, production build and SEO audit pass.

The surrounding examples remain fictional customer support scenarios: unresolved issues, previously attempted troubleshooting, contact preferences, returning chats, handoff briefs and source-linked evidence. No sample counts are customer results. References used for the context examples: Salesforce's [omnichannel customer service explanation](https://www.salesforce.com/service/what-is-customer-service/omnichannel-customer-service/) and Zendesk's [customer context guide](https://www.zendesk.com/blog/customer-service/support/customer-service-agents-need-context/).

Node and Vite now return real 206 byte-range responses for the soundtrack. Without ranges, Chromium reported a seekable range of 0–0 even with the whole file buffered, resetting scrubs to the beginning. The shared range handler covers exact, open-ended, suffix, invalid, conditional and HEAD requests; static CDNs continue to serve the same asset directly. Native audio completion publishes the final replay state even when animation frames are throttled.
