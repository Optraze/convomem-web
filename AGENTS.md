# AGENTS.md — convomem-web

Guidance for AI coding agents (Claude Code, Greptile, Cursor, Copilot, etc.) working in this repository.

## What this repo is

ConvoMem's public marketing site: landing page, blog, changelog, and docs, all statically/SSR-rendered from MDX content.

Stack: **TanStack Start** (full-stack React, SSR) + TanStack Router (file-based, `tsr generate`) + TanStack React Query + Tailwind 4 + Base UI + MDX (`@mdx-js`) for content + Bun as the runtime/package manager + Biome for lint/format (not ESLint/Prettier).

## Structure

```
src/
├── routes/           # file-based routes (TanStack Router) — index, contact, terms, privacy
│   ├── blog/         # index + $slug
│   ├── changelog/    # index + $slug
│   ├── docs/         # index + $slug
│   └── api/og.tsx     # OG image route
├── content/           # blog/, changelog/, docs/ — MDX source
├── components/, features/, hooks/, lib/, types/
└── routeTree.gen.ts   # generated by `tsr generate` — never hand-edit

scripts/
├── generate-sitemap.ts, generate-og.tsx, generate-llms.ts   # run in `prebuild`
└── content-files.ts
```

## Commands

```bash
bun install
bun run dev          # vite dev --port 3000
bun run build         # runs prebuild (sitemap + OG + llms.txt generation) then vite build
bun run generate-routes   # tsr generate — run after adding/removing a route file
bun run typecheck     # tsc --noEmit
bun run check         # biome check --write .   (lint + format together)
bun test              # vitest run
```

## Conventions

- **Bun, not npm/yarn/pnpm** — use `bun` for install/run/test.
- **Biome, not ESLint/Prettier** — `bun run check` is the one command for lint+format; don't add ESLint/Prettier config.
- Content (blog posts, changelog entries, docs pages) lives as MDX under `src/content/` — adding a page means adding an MDX file there plus, if it's a new section, a matching `$slug.tsx` route, not hand-writing a new React page for prose content.
- `routeTree.gen.ts` is generated by `bun run generate-routes` — never hand-edit it; regenerate after adding/removing/renaming a route file under `src/routes/`.
- `prebuild` regenerates the sitemap, OG images, and `llms.txt` from content — if you add a new content type or route, check whether `scripts/generate-sitemap.ts`/`generate-llms.ts` needs to pick it up too, or new pages will be invisible to search/AI crawlers.

## Workflow

1. For a new marketing/blog/docs page: add the MDX content first, then wire the route if it's a new section (follow the existing `blog/`/`changelog`/`docs` pattern rather than inventing a new one).
2. Run `bun run generate-routes` after touching anything under `src/routes/`.
3. Run `bun run check` and `bun run typecheck` before considering a change done.
4. This is a public, unauthenticated site — no customer data, memory content, or auth tokens belong here. If a task asks to embed live product data, that's a signal to double check scope before proceeding.
