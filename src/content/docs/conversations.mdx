Conversations track customer sessions across channels. An active conversation is reused
for subsequent captures until it ends or times out.

<Callout type="tip" title="Closing on the last capture">
When you are sending the final turns anyway, close the conversation on that capture with
`endConversation: true` or `escalate: true` (see [Capture](/docs/capture)). That keeps the
order transcript → memories → close → analysis. Use the endpoints on this page when
there are no turns left to send.
</Callout>

## Start

Begin a new conversation for a customer.

<CodeTabs>
  <CodeTab language="curl" filename="Terminal">
  ```bash
  curl -s -X POST -H "X-API-Key: $CONVOMEM_API_KEY" \
    -H "Content-Type: application/json" \
    "https://api.convomem.com/api/v1/customers/f3b39d1b-2522-4a00-98df-8cdde783ba12/conversations" \
    -d '{"channel": "CHAT"}'
  ```
  </CodeTab>
  <CodeTab language="typescript" filename="start.ts">
  ```typescript
  const conversation = await client.startConversation(
    { customerId: 'f3b39d1b-2522-4a00-98df-8cdde783ba12' },
    { channel: 'CHAT' },
  )

  console.log('Conversation:', conversation.id)
  console.log('Status:', conversation.status)
  ```
  </CodeTab>
  <CodeTab language="python" filename="start.py">
  ```python
  from convomem import CustomerIdentity

  identity = CustomerIdentity(customer_id="f3b39d1b-2522-4a00-98df-8cdde783ba12")
  conversation = client.start_conversation(identity, "CHAT")

  print(f"Conversation: {conversation.id}")
  print(f"Status: {conversation.status}")
  ```
  </CodeTab>
  <CodeTab language="rust" filename="main.rs">
  ```rust
  use convomem::CustomerIdentity;

  let identity = CustomerIdentity::from_id("f3b39d1b-2522-4a00-98df-8cdde783ba12");
  let conversation = client.start_conversation(&identity, "CHAT").await?;

  println!("Conversation: {}", conversation.id);
  println!("Status: {}", conversation.status);
  ```
  </CodeTab>
</CodeTabs>

## List

List all conversations for a customer with pagination.

<CodeTabs>
  <CodeTab language="curl" filename="Terminal">
  ```bash
  curl -s -H "X-API-Key: $CONVOMEM_API_KEY" \
    "https://api.convomem.com/api/v1/customers/f3b39d1b-2522-4a00-98df-8cdde783ba12/conversations?page=1&limit=20"
  ```
  </CodeTab>
  <CodeTab language="typescript" filename="list.ts">
  ```typescript
  const { conversations, total } = await client.listConversations(
    { customerId: 'f3b39d1b-2522-4a00-98df-8cdde783ba12' },
    { page: 1, limit: 20 },
  )

  for (const conv of conversations) {
    console.log(`${conv.id}: ${conv.status} (${conv.channel})`)
  }
  ```
  </CodeTab>
  <CodeTab language="python" filename="list.py">
  ```python
  result = client.list_conversations(identity, page=1, limit=20)

  for conv in result.conversations:
      print(f"{conv.id}: {conv.status} ({conv.channel})")
  ```
  </CodeTab>
  <CodeTab language="rust" filename="main.rs">
  ```rust
  let result = client.list_conversations(&identity, Some(1), Some(20), None).await?;

  for conv in &result.conversations {
      println!("{}: {} ({})", conv.id, conv.status, conv.channel);
  }
  ```
  </CodeTab>
</CodeTabs>

## End

End a conversation with an optional outcome. The REST endpoint returns the updated
conversation; the SDK methods return nothing on success.

<CodeTabs>
  <CodeTab language="curl" filename="Terminal">
  ```bash
  curl -s -X PATCH -H "X-API-Key: $CONVOMEM_API_KEY" \
    -H "Content-Type: application/json" \
    "https://api.convomem.com/api/v1/customers/f3b39d1b-2522-4a00-98df-8cdde783ba12/conversations/87c53d10-85f8-4447-920f-b1e847c23a1a" \
    -d '{"outcome": "resolved"}'
  ```
  </CodeTab>
  <CodeTab language="typescript" filename="end.ts">
  ```typescript
  await client.endConversation(
    '87c53d10-85f8-4447-920f-b1e847c23a1a',
    { customerId: 'f3b39d1b-2522-4a00-98df-8cdde783ba12' },
    { outcome: 'resolved' },
  )
  ```
  </CodeTab>
  <CodeTab language="python" filename="end.py">
  ```python
  client.end_conversation(
      "87c53d10-85f8-4447-920f-b1e847c23a1a",
      identity,
      outcome="resolved",
  )
  ```
  </CodeTab>
  <CodeTab language="rust" filename="main.rs">
  ```rust
  client.end_conversation(
      Some("87c53d10-85f8-4447-920f-b1e847c23a1a"),
      &identity,
      Some("resolved"),
  ).await?;
  ```
  </CodeTab>
</CodeTabs>

## By identity (flat routes)

When you only have an email, phone, or external ID, use
`POST /customers/conversations/end` and `POST /customers/conversations/escalate` with the
identity in the body. These routes resolve the customer and act on that customer's
**active** conversation. They do not take a `conversationId`, and return `404` when the
customer has no active conversation.

```bash title="Terminal"
curl -s -X POST -H "X-API-Key: $CONVOMEM_API_KEY" \
  -H "Content-Type: application/json" \
  "https://api.convomem.com/api/v1/customers/conversations/end" \
  -d '{"email": "alice@example.com", "outcome": "resolved"}'
```

The SDKs use these routes automatically when you pass no `conversationId` or no
`customerId`:

```typescript
await client.endConversation(null, { email: 'alice@example.com' }, { outcome: 'resolved' })
```

## Response fields

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Unique conversation identifier |
| `customerId` | string | Associated customer ID |
| `channel` | string | Channel: `VOICE`, `CHAT`, `SMS`, or `EMAIL` |
| `status` | string | Status: `ACTIVE`, `COMPLETED`, `ESCALATED`, or `ABANDONED` |
| `startedAt` | string | ISO-8601 start timestamp |
| `endedAt` | string | ISO-8601 end timestamp (if ended) |

## Channel types

| Value | Description |
| --- | --- |
| `CHAT` | Web chat, live chat widget |
| `VOICE` | Phone call, voice agent |
| `SMS` | Text message |
| `EMAIL` | Email thread |
