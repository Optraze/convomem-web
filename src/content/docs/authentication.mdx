ConvoMem is built to hold sensitive customer data responsibly. This guide covers how you
authenticate and how your data is protected.

## API keys

Every request is authenticated with an `X-API-Key` header:

```typescript title="request.ts"
const res = await fetch('https://api.convomem.com/api/v1/customers?limit=1', {
  headers: {
    'X-API-Key': process.env.CONVOMEM_API_KEY!,
  },
})
```

The SDK handles auth automatically — pass your key at initialization:

```typescript title="init.ts"
import { ConvoMem } from '@optraze/convomem-sdk'

const client = new ConvoMem({
  apiKey: process.env.CONVOMEM_API_KEY!,
})
```

<Callout type="note" title="No Bearer prefix">
ConvoMem uses `X-API-Key` header authentication, not `Authorization: Bearer`.
</Callout>

## Keys are bound to one agent

Every API key belongs to exactly one **agent** — the workspace that owns a given bot
or use case (see [the memory model](/docs/memory-model)). You choose the agent when
you create the key, and it cannot be changed afterwards.

That binding decides where your data goes and what comes back:

- Captures land under that agent, and are extracted using **that agent's** capture prompt
- Recall and lookups return only that agent's memories and conversations
- Webhooks fire only for that agent's events

So two keys behave like two separate datasets, even for the same customer:

```typescript title="two-agents.ts"
const support = new ConvoMem({ apiKey: process.env.SUPPORT_KEY! }) // support agent
const sales   = new ConvoMem({ apiKey: process.env.SALES_KEY! })   // sales agent

// Same person — one customer record shared across the organization…
await support.capture(
  [{ role: 'user', content: 'My bag never arrived in Lisbon.' }],
  { email: 'jane@example.com' },
)
await sales.capture(
  [{ role: 'user', content: 'What would a business class upgrade cost?' }],
  { email: 'jane@example.com' },
)

// …but each key only ever sees its own agent's memories.
const ctx = await support.lookup('recent issues', { email: 'jane@example.com' })
// → the missing bag, never the upgrade enquiry
```

<Callout type="warning" title="Use the right key per bot">
Pointing your sales bot at the support agent's key silently files its conversations
under support and extracts them with the wrong prompt. Nothing errors — the data just
ends up in the wrong place. Give each bot its own key.
</Callout>

If a key's agent is paused or archived in the dashboard, its captures start returning
`403 FORBIDDEN` until the agent is active again.

## Scopes

Organization API keys (`sk-org-*`) have **integration scope** and can access:

- Capture (`POST /capture`)
- Customer management (`/customers/*`)
- Memory management (`/customers/*/memories`)
- Conversations (`/customers/*/conversations`)
- Handoff briefings (`/customers/*/handoff`, `/customers/handoff`)
- Embed tokens (`/embed/tokens`)

Administrative endpoints — webhooks management, org settings, audit logs, and analytics
dashboards — require session-based authentication through the dashboard. They **cannot**
be accessed with an org API key.

<Callout type="danger" title="Rotate compromised keys immediately">
If a key leaks, revoke it from the dashboard. Revocation takes effect within seconds and
cannot be undone.
</Callout>

## PII redaction

Before any memory is persisted, ConvoMem runs detection for emails, phone numbers, card
numbers, and other sensitive patterns, replacing them with typed placeholders. The
original values are never written to long-term storage.

## Data residency

Choose where your data lives at the project level. On-prem and single-tenant deployments
are available for regulated workloads — see the [changelog](/changelog) for the latest
availability.
