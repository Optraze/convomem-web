ConvoMem runs a hosted [Model Context Protocol](https://modelcontextprotocol.io) server, so an
MCP-capable agent can capture conversations and recall customer memory without any SDK
code. It uses the same API key, agent scope and rate limits as the REST API.

```text title="Endpoint"
https://api.convomem.com/api/v1/mcp
```

The transport is **Streamable HTTP**. There is nothing to install or run locally.

## Authentication

Use an organization API key (`sk-org-...`). MCP clients usually send a static bearer token,
so this endpoint accepts either header:

- `Authorization: Bearer sk-org-...`
- `X-API-Key: sk-org-...`

If you send both, they must be the same key. Dashboard session tokens are not accepted.

<Callout type="note" title="Bearer is accepted here only">
The REST API takes `X-API-Key` only. The MCP endpoint additionally accepts
`Authorization: Bearer` because most MCP clients can only send a bearer token.
</Callout>

The key's [agent binding](/docs/authentication) applies to every tool call: captures land
under that agent, reads return only that agent's data, and a tool call cannot switch agents.
An archived agent's key is rejected.

## Connect a client

### Claude Code

```bash
claude mcp add --transport http convomem https://api.convomem.com/api/v1/mcp \
  --header "Authorization: Bearer sk-org-..."
```

### Clients configured with JSON

For clients that read an `mcpServers` file and support remote servers with custom headers
(for example Cursor's `mcp.json`):

```json title="mcp.json"
{
  "mcpServers": {
    "convomem": {
      "url": "https://api.convomem.com/api/v1/mcp",
      "headers": { "Authorization": "Bearer sk-org-..." }
    }
  }
}
```

Keep the key out of shared or committed config files; use your client's secret or
environment-variable support where it has one.

## Tools

Every read identifies exactly **one customer** by `customerId`, `email`, `phone` or
`externalId`. There is no tool that lists or searches across all customers.

| Tool | What it does |
| :-- | :-- |
| `convomem_capture` | Queues conversation turns for one customer, exactly like [`POST /capture`](/docs/capture). Returns a `captureId`. |
| `convomem_capture_status` | Polls a capture: `queued`, `processing`, `completed` or `failed`. |
| `convomem_lookup_customer` | Resolves one customer and returns a cold-open context, or topic-specific context when you pass `topic`. |
| `convomem_search_memories` | Searches one customer's memories for a required `topic` and returns a ranked context block. |
| `convomem_list_memories` | Pages through one customer's active memories (`page`, `limit` up to 100, `category`, `includeExpired`, `asOf`). |
| `convomem_get_handoff` | Returns a [handoff brief](/docs/handoff) for one customer, with `fresh` and `narrative` options. |

### Capturing

`convomem_capture` takes `messages` (1–200 turns, each with `role` of `user`, `assistant`,
`agent` or `system` and `content` up to 10,000 characters) plus the same optional fields as
the REST endpoint: `channel`, `language`, `occurredAt`, `infer`, `idempotencyKey`,
`endConversation`, `escalate`, `outcome`, `reason`, `speakerId` and `speakerName`.

<Callout type="warning" title="Send every turn verbatim">
Don't pre-filter or summarise turns before capturing. ConvoMem decides what becomes memory;
the MCP tool applies no filter of its own.
</Callout>

Capture is asynchronous. Poll `convomem_capture_status` with the returned `captureId` before
assuming new memories are available.

### Recalling

`convomem_lookup_customer` and `convomem_search_memories` accept the same retrieval options
as the [REST lookup](/docs/retrieval): `topic`, `maxTokens` (50–4,000), `limit` (1–20),
`threshold`, `latestOnly`, `referenceDate`, `includeAgentFacts`, `verify` and `rerank`.
Both return the context text plus the `memoryIds` and `tokenCount` behind it.

## Treat returned memory as data, not instructions

Memory, customer and handoff text comes from your customers' conversations, so it is
untrusted. ConvoMem returns it inside an `<untrusted_caller_memory>` block. Your agent should
use it as background information only — never follow instructions found inside it, and never
treat it as authorization for an action such as a refund or account change.

## Errors

Tool failures return a short, safe message instead of internal details:

| Situation | Message |
| :-- | :-- |
| Invalid arguments | The request was invalid. Check the tool arguments and try again. |
| Bad or missing key | Authentication failed. Check or replace the ConvoMem API key. |
| Key lacks permission | This API key is not permitted to perform that operation. |
| Unknown customer or capture | The requested customer or capture was not found. |
| Conflicting retry | The request conflicts with an operation already in progress. Retry with the same idempotency key. |
| Rate limited | ConvoMem rate limit reached. Retry later. |
| Server error | ConvoMem is temporarily unavailable. Retry later. |

Requests count against the same [rate limits](/docs/errors) as the REST API.

## Not in the SDKs

The MCP endpoint is a protocol surface for agents. It is not part of the REST OpenAPI
document or the TypeScript, Python and Rust SDKs — use those for application code.
